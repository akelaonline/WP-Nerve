# WPNerve 0.1.0-alpha.15 — Final Product Polish

Alpha.15 closes the operator-facing product pass after visual QA on a real WordPress staging installation and synchronizes the release candidate around one exact version contract.

## What changed

- Diagnostics uses the same WPNerve product shell as Dashboard, HTTP Smoke and Documentation: runtime KPI cards, protocol/database state, operational smoke evidence, staging controls and blocked-ability reporting.
- Package metadata, README/readme history and version mirrors are aligned to `0.1.0-alpha.15`.
- The final admin stylesheet preserves both the dedicated Diagnostics table/card rules and the professional fallback treatment for remaining product screens.
- Generated localization templates are kept out of the installable alpha artifact; runtime text-domain behavior is unchanged.
- Release documentation distinguishes the staging evidence already obtained from the production-readiness gates that still require execution.

## Real staging evidence carried forward

The operational staging smoke already passed with the 53-ability catalog model:

- 53/53 registered and discoverable in explicit full-surface staging mode;
- `server/discover` and `tools/list` (53 tools);
- `site-status` and `list-plugins`;
- draft creation and content update;
- destructive confirmation issuance and administrator approval;
- trash and restore;
- unauthenticated public endpoint rejection with HTTP 401.

Alpha.15 does not weaken or replace those runtime controls; it finalizes the operator/release surface around them.
